# Prove the changed behavior

## Establish identity first

Record the exact requested URL/runtime, repository branch/revision and relevant working changes or file hashes. A live build may differ from both its image tag and HEAD. Inspect startup/mount/payload evidence as appropriate. Do not test a convenient neighboring container or stale packaged renderer. A 200 response or healthy login page only proves reachability.

Discover the current hosting instance and selected development/test target from the task record. Use the explicitly configured target, otherwise the hosting instance. Report an invalid or unreachable explicit target without silently falling back; do not hardcode a former installation or select a convenient neighboring instance. Inside Docker, localhost and paths refer to that container. Host repositories require authorized host tools or a verified accessible checkout.

Agent Zero framework/API/hooks run under `/opt/venv-a0/bin/python`; agent terminal code uses `/opt/venv/bin/python`. Verify backend loading in the framework runtime. Do not install a package in the execution runtime and claim backend compatibility.

Apply the shared team contract: record hosting and selected target identities, actual checkout/binds, staging branch, dirty state and artifact identity. Missing explicit target configuration uses the hosting instance and does not block work. Same-instance product writes/tests follow normal authorization. If a reload/restart would interrupt active workers on the selected target, checkpoint and coordinate their work using existing lifecycle mechanisms as needed. Verify the actual backing paths of an explicitly different target; a branch/worktree alone does not identify its runtime. Pure helper fixtures establish only their bounded behavior. Wait for dependent writers before integration checks. Verify every commit has a meaningful subject and body separated by actual newlines.

## Choose checks from the obligation

Use existing project checks and the existing `a0-e2e-testing` skill for browser/Agent Zero mechanics. No fixed full-suite sweep for a trivial edit. New consequential logic needs a meaningful behavior check; tests mirroring implementation wording are insufficient.

For profiles/skills: validate native catalog visibility, actual skill load/reference reads, rendered prompt inheritance, distinct role responsibilities and effective model scope. Then exercise a benign fresh chat with native delegation if authorized/configured. Static success does not establish autonomous coordination.

For native browser coverage, use Agent Zero's `browser` tool and its selected container/connector runtime. A Codex browser or host Playwright action is not a child capability test. Report actual child host-file read/write modes and missing capabilities separately from unrelated checks.

For user-visible work: perform the actual action and inspect its postcondition; save/reopen/reload when persistence is requested. For performance: equivalent starting conditions, real measurements and unchanged correctness. For upgrades/data: isolated old-state fixtures and recovery, never destructive live-user experiments.

For plugin/backend code: confirm files in the intended runtime, then restart only if required by current lifecycle guidance and authorization. A verified bind mount does not need a redundant file copy. Do not restart a user's active instance merely to discover new user profiles. Recheck changed behavior plus a relevant neighbor, not unrelated features.

## Evidence and bounded cleanup

Use a unique task/run label. Keep temporary records, settings and processes task-owned. Preserve existing chats, presets, permissions and connectors. Remove or stop only what this run created; retain requested evidence and name any residue. Mask secrets before logging, never dump settings or transcripts.

Return a compact table: acceptance case; expected; observed; PASS/FAIL/BLOCKED/NOT RUN; evidence location. Label evidence as static, focused automated, UI-observed or live model-driven. A tool invocation receipt is not its postcondition. An unavailable model/browser/credential is BLOCKED; an unattempted case is NOT RUN. One informed retry after a transient failure is reasonable; stop repeated identical failures and report the actual limitation. Do not “repair” an unrelated product issue to make a pilot pass.
